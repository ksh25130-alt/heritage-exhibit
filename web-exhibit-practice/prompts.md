# AI에게 보내는 단계별 요청문

`plan.md`와 `sources.md`가 있는 작업 폴더를 Codex 또는 Antigravity에서 연 다음 사용합니다. 전체를 한꺼번에 보내지 말고, 단계의 결과를 확인한 뒤 다음 요청을 보냅니다.

## 1. 기획과 자료를 읽게 하기

```text
현재 작업 폴더의 plan.md와 sources.md를 읽어줘.
전시 의도, 관람 대상, 화면별 자료와 관람 행동을 요약해줘.
실제 폴더의 파일도 확인해서 없는 자료를 알려줘.
확인되지 않은 유물 정보와 이미지를 만들지 마.
HTML·CSS·JavaScript만 사용하는 빌드 없는 정적 웹사이트로
GitHub Pages에 공개할 계획이야.
아직 코드를 수정하지 말고, 구현 순서와 확인이 필요한 점을 먼저 보여줘.
```

Antigravity의 계획 기능을 사용할 때는 이 요청 앞에 `/plan`을 붙입니다. Codex에서는 계획 모드를 사용할 수 있으면 선택하거나, 위처럼 먼저 계획만 요청합니다.

**내가 확인할 것:** AI가 정리한 관람 대상과 핵심 질문이 내 의도와 같은가? 파일이 있다고 잘못 가정하지 않았는가? 이번에 필요하지 않은 기능을 추가하지 않았는가?

## 2. 첫 화면과 관람 흐름 만들기

```text
확인한 계획으로 첫 구현을 진행해줘.
도입, 첫 자료, 마무리가 이어지는 작은 초안부터 만들어줘.
index.html, style.css, script.js로 구성하고 상대경로를 사용해줘.
사진이 없으면 자료명과 '자료 이미지 준비 중'을 보여줘.
코드만 답변에 붙이지 말고 현재 작업 폴더에 실제 파일을 만들어줘.
내 컴퓨터에서 확인할 수 있게 실행하고, 열어야 할 주소와 종료 방법을 알려줘.
실행에 필요한 도구가 없다면 먼저 설치 여부를 확인하고 가장 간단한 방법을 제안해줘.
완료 후 만든 파일과 내가 직접 눌러 볼 항목을 알려줘.
```

## 3. 실제 자료 연결과 핵심 기능

```text
plan.md의 나머지 자료 구간을 추가해줘.
sources.md와 assets 폴더를 대조하고, 실제 파일명으로 연결해줘.
작품명, 해설, 출처가 같은 자료를 가리키는지 확인해줘.
이미지 크게 보기와 닫기를 구현해줘.
닫으면 원래 읽던 위치와 버튼으로 돌아와야 해.
휴대폰과 키보드에서도 사용할 수 있게 해줘.
이미지가 없는 경우에는 준비 중 안내를 유지해줘.
```

## 4. 화면을 보고 수정 요청

```text
첨부한 화면은 첫 번째 자료 구간이야.
문제: 휴대폰 폭에서 닫기 버튼이 화면 밖으로 나가.
재현: 첫 자료의 크게 보기를 누른 다음 화면을 세로로 보면 나타나.
원하는 결과: 닫기 버튼이 항상 보이고 누르면 읽던 위치로 돌아오게 해줘.
이 문제와 관련된 부분만 수정한 뒤 같은 순서로 다시 확인해줘.
수정한 파일과 확인 결과를 알려줘.
```

실제 문제에 맞춰 위치·재현 순서·결과를 바꾸고 화면 캡처를 첨부합니다. AI가 확인했다고 답해도 학생이 같은 동작을 직접 실행합니다.

## 5. 공개할 파일 준비

```text
이 전시를 GitHub Pages에서 공개할 준비를 해줘.
저장소 이름은 heritage-exhibit이고 main 브랜치의 최상위 폴더를 쓸 거야.
index.html이 최상위에 있고, CSS·JS·이미지가 상대경로인지 확인해줘.
서버나 별도 빌드 없이 동작하는지도 확인해줘.
개인정보, 계정 정보, 비밀키, 불필요한 원본 파일이 있는지 점검해줘.
sources.md에서 공개 이용 조건을 확인하지 못한 자료를 알려줘.
미확인 자료는 공개 파일에 넣지 말고 준비 중 표시를 유지해줘.
GitHub에 올릴 정확한 파일 목록과 제외할 목록을 정리해줘.
README.md에 실행·공개·수정 방법을 작성해줘.
공개 업로드는 내가 직접 진행할게.
```

## 6. 공개 후 이미지가 안 보일 때

```text
로컬에서는 이미지가 보이는데 GitHub Pages에서는 보이지 않아.
공개 주소: [실제 공개 주소]
문제가 있는 자료: [자료명]
실제 저장소 경로: [예: assets/school.jpg]
화면 또는 오류 문구: [붙여넣기]
파일명 대소문자와 상대경로, 저장소 하위 경로를 확인해줘.
원인을 설명하고 필요한 파일만 수정해줘.
수정 후 다시 올릴 파일과 공개 화면에서 확인할 동작도 알려줘.
```

## 7. 수업이 끝나기 전

```text
현재 작동하는 범위, 실행 방법, 아직 안 되는 기능,
추가로 확인할 자료를 submission.md에 정리해줘.
내가 실제로 확인하지 않은 테스트를 완료로 표시하지 마.
다음에 이 폴더를 열면 어디서 이어서 작업하면 되는지도 적어줘.
```
