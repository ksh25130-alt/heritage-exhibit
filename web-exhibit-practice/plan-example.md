# 옛사람들의 눈에 비친 아이들

> 수업용 웹전시 기획 예제입니다. 국립중앙박물관의 공식 전시를 그대로 재현한 기획서가 아닙니다. 자료 사진은 별도로 준비합니다.

## 1. 기획 의도

그림과 공예품에 표현된 아이들을 함께 보며, 옛사람들이 아이들의 일상과 아이에게 거는 바람을 어떻게 남겼는지 생각하게 합니다.

- 핵심 질문: 문화유산 속 아이들의 모습에서 어떤 삶과 바람을 읽을 수 있을까요?
- 관람 대상: 초등학교 고학년과 보호자.
- 관람 시간: 약 5분.
- 관람 후 남길 생각: 같은 ‘아이’라는 소재도 자료의 쓰임과 표현에 따라 다른 이야기를 전할 수 있다.
- 제목 아래 소개: ‘배우고, 춤추고, 누군가의 바람이 된 아이들. 세 자료를 가까이 보며 아이들을 바라본 시선을 찾아봅니다.’

## 2. 전시에 사용할 자료

자료명과 역사 정보는 `sources.md`의 공식 자료를 확인합니다. 아래 해설은 관찰을 안내하기 위한 수업용 초안입니다. 제작자가 확인하지 않은 연대·크기·의미·소장번호를 AI가 추가하지 않습니다.

| ID | 자료 | 화면에서 맡는 역할 | 이미지 경로 | 초기 상태 |
| --- | --- | --- | --- | --- |
| A01 | 김홍도, 서당 | 아이의 표정과 주변 사람의 관계를 관찰 | `./assets/school.jpg` | 사진 준비 전 |
| A02 | 김홍도, 춤추는 아이 | 몸짓과 함께 등장하는 사람을 관찰 | `./assets/dance.jpg` | 사진 준비 전 |
| A03 | 포도·동자무늬 청자 주자 | 공예품에 표현된 아이와 바람을 생각 | `./assets/pitcher.jpg` | 사진 준비 전 |

- 각 이미지의 소장기관 표시는 국립중앙박물관으로 합니다. 정식 작품명은 공개 전 원 자료와 대조합니다.
- 이미지가 없거나 불러오기에 실패하면 해당 자료명과 ‘자료 이미지 준비 중’을 보여줍니다. 임의의 AI 유물 그림이나 다른 사진으로 대체하지 않습니다.
- 출처·사진 이용 조건이 미확인인 파일은 공개 폴더에 포함하지 않습니다. 빈자리로 공개하고 사진을 준비한 뒤 교체할 수 있습니다.

## 3. 이야기의 전개

한 페이지를 아래로 읽는 전시입니다. 위에는 제목과 ‘관람 시작’ 버튼, 아래에는 세 자료와 마무리 질문이 이어집니다. 별도 로그인이나 회원 기능은 없습니다.

| 구간 | 관람자가 보는 것 | 화면에 넣을 문장 | 관람자의 행동과 반응 |
| --- | --- | --- | --- |
| 도입 | 전시 제목, 핵심 질문, 소개, 관람 시작 버튼 | ‘옛사람들은 아이들의 모습을 어떻게 남겼을까요?’ | 시작을 누르면 첫 자료로 이동 |
| 1. 배우는 아이 | 서당 전체 이미지, 짧은 해설 | ‘가운데 아이의 표정과 주변 사람의 시선을 보세요. 이 장면에 어떤 일이 있었을지 생각해 봅시다.’ | ‘크게 보기’를 누르면 확대 창이 열림 |
| 2. 움직이는 아이 | 춤추는 아이 이미지, 짧은 해설 | ‘아이의 몸짓과 함께 등장하는 사람들을 보세요. 화면에서 움직임이 느껴지는 부분을 찾아봅시다.’ | 다음 자료로 이동하거나 다시 확대 |
| 3. 바람을 담은 아이 | 청자 주자 전체 이미지, 짧은 해설 | ‘그릇에 표현된 아이는 어떤 바람과 연결될까요? 공식 자료의 설명과 그림의 표현을 함께 살펴봅니다.’ | 출처를 열어 원문과 비교 |
| 마무리 | ‘아이의 일상’과 ‘아이에게 거는 바람’을 돌아보는 질문 | ‘세 자료 중 하나를 고른다면, 어떤 아이의 모습을 기억하고 싶나요?’ | 생각해 본 뒤 ‘처음으로’ 선택 |
| 출처 | 작품별 자료명, 소장기관, 원문 링크, 이용 조건 | `sources.md`에서 확인된 항목만 표시 | 공식 원문을 새 탭으로 열기 |

마지막 질문의 답은 화면에 입력하거나 서버에 저장하지 않습니다. 관람자가 스스로 생각하거나 수업에서 말로 나누는 질문입니다.

## 4. 핵심 기능: 이미지 크게 보기

- 모든 자료에 ‘크게 보기’ 버튼을 둡니다. 이미지가 준비되지 않았으면 버튼을 비활성화하고 이유를 표시합니다.
- 버튼을 누르면 같은 작품의 큰 이미지, 작품명, 같은 해설을 대화상자 안에 표시합니다.
- 닫기 버튼과 Esc 키로 닫을 수 있습니다.
- 열린 동안 키보드 초점이 대화상자 안에서 이동합니다. 닫으면 누른 버튼으로 초점이 돌아옵니다.
- 닫은 뒤 읽던 스크롤 위치가 유지됩니다.
- 터치 화면에서는 닫기 버튼이 화면 밖으로 나가지 않아야 합니다.
- 이번에는 이미지의 픽셀을 확대하는 복잡한 줌·이동 기능까지 요구하지 않습니다. 큰 화면에서 작품을 확인하는 기능부터 완성합니다.

## 5. 화면의 느낌과 읽기 쉬움

- 바탕은 따뜻한 밝은색, 본문은 진한 녹색 또는 먹색, 강조색은 갈색 계열을 씁니다.
- 작품 사진과 짧은 질문이 먼저 보이게 합니다. 한 자료의 안내 문장은 2~3문장으로 제한합니다.
- 데스크톱에서는 이미지와 해설을 나란히, 휴대폰에서는 이미지 아래에 해설을 놓습니다.
- 사진은 자르거나 늘려서 변형하지 않고 원본 비율을 유지합니다.
- 본문은 최소 18px, 버튼의 터치 영역은 최소 44×44px로 설계합니다.
- 이미지에는 자료명과 관찰할 내용을 담은 대체 텍스트를 넣습니다.
- 키보드로 버튼을 찾을 수 있도록 초점을 표시하고, 자동재생·번쩍임·과한 움직임을 사용하지 않습니다.
- 390px와 1280px 화면 폭에서 가로 스크롤이나 겹침이 없어야 합니다.

## 6. 제작과 공개 방식

GitHub Pages에 올릴 **빌드 없는 정적 웹사이트**로 제작합니다.

| 파일 | 역할 |
| --- | --- |
| `index.html` | 첫 화면부터 출처까지 연결된 전시 본문 |
| `style.css` | 화면 배치, 글자, 색상, 휴대폰 대응 |
| `script.js` | 확대 창과 이동 등 관람 행동 |
| `assets/school.jpg` 등 | 공개 이용 조건을 확인한 실제 자료 이미지 |
| `README.md` | AI가 작성할 실행 방법과 공개 방법 |
| `plan.md`, `sources.md` | 제작 기준과 출처 기록 |

- HTML·CSS·JavaScript만 사용합니다. 첫 실습에서 React·Vite·패키지 설치·별도 빌드·서버 프로그램을 추가하지 않습니다.
- 모든 내부 파일은 `./style.css`, `./script.js`, `./assets/school.jpg`처럼 상대경로로 연결합니다.
- 유물 이미지 파일을 외부 주소에서 직접 불러오는 방식에 의존하지 않습니다.
- 회원가입, 결제, 데이터베이스, 서버 저장, 외부 AI API 호출은 이번 범위에 없습니다.
- 비밀키나 개인 계정 정보가 없어도 관람할 수 있어야 합니다.
- 로컬 실행은 설치된 환경을 먼저 확인한 뒤 가장 간단한 미리보기 방법을 안내합니다. 새 도구 설치가 필요하면 이유와 대안을 알려줍니다.
- 공개 저장소 이름은 `heritage-exhibit`, 브랜치는 `main`, Pages 폴더는 `/(root)`를 기준으로 합니다. 실제 계정 이름은 제작자가 입력합니다.

## 7. 구현 순서

1. 이 문서와 `sources.md`, 실제 폴더의 파일을 읽습니다. 기획과 누락 자료를 요약하고 구현 계획을 먼저 보여줍니다.
2. 확인한 뒤 도입·첫 자료·마무리가 이어지는 초안을 만듭니다.
3. 실제 파일을 연결하고 나머지 두 자료를 추가합니다.
4. 크게 보기와 닫기 기능을 완성합니다.
5. 데스크톱과 휴대폰 크기에서 확인하고 발견한 오류를 고칩니다.
6. 공개할 파일과 이용 조건을 확인하고 GitHub Pages에 게시합니다.
7. 공개 주소를 다른 사람의 휴대폰에서 열어 다시 확인합니다.

## 8. 완료 기준

- [ ] 첫 화면에서 전시 제목과 핵심 질문을 읽을 수 있다.
- [ ] 관람 시작을 누르면 첫 자료로 이동한다.
- [ ] 세 자료의 이미지와 제목이 서로 일치한다. 미준비 사진은 그 상태를 명확히 표시한다.
- [ ] 준비된 이미지의 크게 보기와 닫기가 작동하고, 읽던 위치로 돌아온다.
- [ ] 키보드와 휴대폰에서도 주요 동작을 수행할 수 있다.
- [ ] 작품마다 출처 링크를 확인할 수 있다.
- [ ] 공개 주소를 로그아웃 상태와 다른 기기에서 열 수 있다.
- [ ] 수정한 파일을 다시 업로드한 뒤 공개 화면에도 변경 사항이 보인다.
- [ ] 사진 미준비·해설 검토 등 남은 일은 `submission.md`에 기록한다.

## 9. 아직 확인할 것

사진의 공개 이용 조건, 정식 작품명, 작품별 세부 해설은 제작자가 확인합니다. 이 확인이 끝나지 않은 상태의 결과물은 ‘교육용 구조 실습본’으로 표시합니다.
